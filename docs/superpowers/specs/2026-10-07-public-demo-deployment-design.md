# 公开演示部署设计

用户明确授权公开演示部署，并给出每月人民币100元以内预算。方案是一个Render小规格应用实例（同时提供构建后的网页及FastAPI），加Neon Free PostgreSQL，使用平台HTTPS网址。费用以资源创建界面为准，不启用付费数据库、自动扩容或收费附加项；账户注册、密码、协议及账单绑定由用户本人完成。备用方案是现有服务器运行同一容器，不临时重写业务或迁移至SQLite。

保留模拟支付、物流、退款；显式公开演示开关才能在production启用现有DEMO事件接口。所有业务权限仍由既有服务控制，不让anonymous绕过demo登录。网页显著说明共享虚构数据、模拟业务、勿填真实信息。访客可使用既有七个虚构客户/商家/调度账号，共享明确公开的演示密码；独立platform/reviewer使用不同的高强度私密密码，绝不在网页/公开API/构建中暴露。公开演示禁止注册、邮件验证/重置/绑定、共享账号改密码和资料/入驻修改；客户地址与业务操作保留并提示只填虚构信息。本机开发模式行为不变。

新增GET /api/commerce/v1/demo-info提供公开演示状态、可用访客账号和公开演示密码；普通环境返回关闭状态，不输出私密管理凭证。前端通过这一公开配置控制入口；生产构建使用同源API，无写入前端的秘密。后端明确允许公开HTTPS origin，限制请求体和登录/写入频率，增加浏览器安全响应头与readiness数据库检查。限流只面向演示单进程实例，不冒充跨实例安全系统；扩容前需共享限流。静态资源仅来自指定dist路径，不提供源码/隐藏文件/任意文件读取。

生产Docker为多阶段Node构建+Python无reload、非root、一个worker。新增独立公开演示启动器：检查生产演示开关/数据库/不同密码/公开URL；标准postgres://或postgresql://云连接规范化到psycopg；迁移head后仅向空commerce账户库显式初始化虚构seed和独立管理账号。重启只验证现有账号及密码相符，不覆盖数据、不清空本机库。预部署失败不启动网页；readiness连接数据库并检查迁移head。原本机schema绝不改为公开数据库。增加受保护pg_dump备份说明和回滚流程。

render.yaml引用本轮候选分支，autoDeployTrigger off，单实例，不依赖main合并；DATABASE_URL及不同密码均由云环境配置。设置存储配额防演示图片占满免费数据库。公开URL需真实HTTPS、浏览器购买/模拟付款/发货/物流/收货及商品图片/权限检查通过，才称发布完成。没有登录云账号时仍完成源码、容器CI、隔离production浏览器和文档，明确唯一剩余的外部条件。
