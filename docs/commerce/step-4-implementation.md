# 第四步：消息与售后

日期：2026-10-07。用户明确授权第四步。实施计划见
[计划](../superpowers/plans/2026-10-07-commerce-step-4.md)。本页记录切片边界；测试结果以独立验证记录为准。

## 授权范围

- 客户与店铺的通用会话、订单会话及双方纯文本消息，真实持久化、分页、刷新读取。
- 已付款未发商品的部分或全额退款；已送达商品在14天内的部分退货退款。
- 客户申请/合法撤销/登记模拟退货，OWNER批准或拒绝、确认全部申请数量退回并选择是否回库、发起退款。
- 独立DEMO操作者提交模拟退款成功/失败；失败后OWNER可发起新尝试。
- 金额、数量、库存、活动Case、订单状态和权限的后端事务约束。
- 当前订单读视图显示所属店铺名称；支付和退款处理中明确说明人工模拟结果步骤。

新行为遵循 [状态规则](lifecycle.md)、[权限](permissions.md)、[API](api.md)，
不引入真实资金、外部消息投递、AI、仲裁、换货或自动退款。

## 核心规则

每订单最多一个活动售后。未发退款申请阻止继续发货；任何活动售后阻止确认收货或修改地址。
申请金额由购买时的单价和申请数量计算，不接受客户端金额。未发商品在退款成功时回库；
退回商品仅在商家确认收货且选择回库时增加库存，退款成功不得再次增加库存。
失败退款不入账、不撤销已确认的物理退货事实；新尝试只能由OWNER发起。

退货要求申请涉及的已发商品全部送达，逐行以最近送达时间计算14天窗口，边界允许。
资格在申请时冻结，不因为审批耗时自动失效。成功退款累计不能超过已付款金额。
退款不擦除原配送时间线、发货量或订单完成时间。

消息不改会话身份、不增长会话版本、不执行HTML或业务动作。商家STAFF可以沟通和读取售后，
不能审批、确认退货或发起退款。暂停店铺可处理已有订单；新通用会话仅在店铺ACTIVE时建立。
