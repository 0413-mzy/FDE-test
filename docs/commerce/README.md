## 冻结决定

| 决定 | v1选择 | 取舍 |
| --- | --- | --- |
| 商品与交易 | 实体商品；币种CNY；整数分；初版运费/税费均0 | 明确可复现，不伪装为真实跨境计价 |
| 多店购买 | 一个Cart；提交时按shop拆成独立Order；一个Checkout记录关联它们 | 独立付款/履约；不引入跨店资金结算 |
| 下单 | 对Cart全部商品原子校验并创建所有店铺订单；任一行失败则全不创建 | 不偷偷买部分商品；返回失败原因 |
| 库存 | 下单预留15分钟，付款消耗预留；超时/未付取消释放 | 控制超卖与重复扣减 |
| 价格 | 购物车保存用户看到的SKU价格版本，提交时要求一致 | 涨价/降价都需用户确认，不静默改价 |
| 支付/物流 | 模拟适配器；结果和时间线持久化，始终标记simulation | 无真实支付、承运商、对外消息 |
| 身份 | 独立CommerceAccount/CommerceSession；客户资格、店铺成员及演示能力分开 | 复用安全原语，不重定义旧客服角色 |
| 消息 | 每个客户/店铺的通用会话或指定本店订单会话；纯文本；刷新读取 | 不先引入附件、群聊或WebSocket |
| 售后 | 未发货数量退款、已送达数量退货退款；每订单最多1个活动Case | 保留分批/部分退款；控制冲突 |
| 发货 | 分包/部分发货；SKU数量守恒；无需取消或修改已发包裹 | 初版不做换货、补发、运单改绑 |
| AI | 不实现；后续有非AI基线与实际样本后单独评估 | 人工业务是可运行的主系统 |

契约更改需同时更新相关文档与验收场景。第二步不实现第三/四步功能，也不自动合并main。

正常演示付款由客户创建Attempt，再由独立DEMO控制台提交成功/失败；
控制台是模拟外部事件入口，不是商家或客户的任意状态修改器。
