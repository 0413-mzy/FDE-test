# 手动物流模拟使用说明

本轮用户批准在原包裹/轨迹基础上增加物流场景控制；无真实快递查询或配送。

## 谁来操作

商家在已付款订单中选择本次发货商品数量，创建独立包裹。登录demo账号，进入模拟事件台的物流控制，选择包裹后推进事件。客户和商家查看同一条轨迹，客户确认收货仍是独立操作。

## 正常流程

已发货/待揽收 → 已揽收 → 运输中 → 派送中 → 物流签收。
按钮按当前状态开放，提交立即生效，不等待现实天数。运输中可增加中转轨迹。物流签收不会替客户点击确认收货。

## 异常场景

运输中选择运输延误，填写虚构原因/地点；解除延误后恢复运输。派送中选择派送失败，填写原因；重新派送后回到派送中。早期历史异常没有细分原因时标为未知，不替旧数据编造原因，人工恢复到运输中。

## 延迟和重复上报

需要模拟接口延迟时，为已经到达的阶段补充较早的事件发生时间。平台同时保存当前接收时间，旧事实不改变包裹当前状态。不能填写未来时间、早于发货的时间，或通过迟报凭空跳到尚未到达的阶段。

重复上报复用同一事件编号和完整内容；相同内容只保存一次，不同内容使用同一编号会被拒绝。遇到版本冲突先刷新包裹，依据最新状态重新选择操作。

已签收包裹保留查询，不删除历史或重置。想重新演示请创建新的虚构订单/包裹。

所有地址、消息和操作备注使用虚构信息；轨迹明确标注模拟来源。数据库保存时间、操作者和修改历史，私有数据中心可查询允许字段。
