# 双端验收矩阵

版本 commerce-v1。下列场景**均未执行**，是实现的验收契约，不是已通过测试。
③指购买/履约闭环，④指消息/售后，⑤指全面异常演示；③④自身必须覆盖相关权限/失败，
不能以“第五步才做异常”为由跳过金额、库存或越权保护。每项记录实际结果、证据与未覆盖项。

## 固定演示夹具

两个客户C1/C2；两家店S1/S2，各有OWNER O1/O2；S1 STAFF T1；DEMO D1（无客户/成员能力）。
演示Seed另有C3（同时S1 OWNER，用于组合能力测试），S1库存负责人始终保留O1。
这些均为虚构账号，无默认源代码密码，显式配置DEMO_SEED_PASSWORD；旧客服Seed不代替它。

SKU A属S1：1000分、5件；B属S2：2000分、3件；L属S1：500分、1件；Z属S1：1000分、0件。
独立场景使用独立schema/Seed或唯一订单，不能依赖前一场景改剩的库存。注入FixedClock
2026-10-06T08:00:00Z；真实双端演示使用SystemClock，不把固定测试时间当实时。

## 正常闭环与持久化

| ID | 阶段 | 操作 | 后端预期 / 双端预期 |
| --- | --- | --- | --- |
| C01 | ③ | O1新建/上架A；C1匿名浏览 | 商品可见，库存/价格来自后端；DRAFT/ARCHIVED不公开 |
| C02 | ③ | C1加入A×2、B×1并下单 | 两店Order，金额2000/2000；A预留2、B预留1；Cart清空 |
| C03 | ③ | 两单各创建付款尝试；D1成功 | 独立PAID/READY_TO_SHIP；A on_hand=3,reserved=0；B=2/0；两店只见本店 |
| C04 | ③ | O1一次发A×2，D1运输/送达，C1确认 | 一包裹SHIPPED→IN_TRANSIT→DELIVERED；Order COMPLETED；双方同时间线 |
| C05 | ③ | O1把A×2分两包发各1件 | 先PARTIALLY_SHIPPED后SHIPPED；两包都送达才可确认 |
| C06 | ③ | 下单后商家改标题/价格，C1改个人输入 | Order仍是原购买快照；价格变化不影响已生成Order |
| C07 | ③ | 双浏览器分别登录；刷新/退出重登/重启服务 | 状态在数据库保留；Bearer不写浏览器存储；刷新需重新登录 |
| C08 | ③ | C1付款尝试失败，期限内重试成功 | 第一失败不扣库存；新尝试成功只扣一次 |
| C09 | ③ | 一个店铺付款失败，另一店成功 | 一单仍待付、一单PAID；无跨店回滚或泄露 |
| C10 | ③ | 未付取消A×2订单 | reserved恢复0，on_hand仍5，CANCELLED/UNPAID |
| C11 | ③ | 客户在允许前态改订单地址 | 保存revision；商家读到新地址；原checkout快照仍保留 |
| C12 | ④ | C1建S1通用及本单会话，双方发消息 | 绑定唯一；文本持久化、时间顺序一致，刷新可读 |
| C13 | ④ | 已付A×2未发，退款1件；O1批准、发起；D1成功 | 退款1000，A回库1；剩1可发，financial PARTIALLY_REFUNDED |
| C14 | ④ | 已付A×2全未发退款成功 | 全额2000、回库2、CANCELLED/REFUNDED；不能后续发货 |
| C15 | ④ | A×2发1件，余1退款成功 | 有效量1已发，Order变SHIPPED；只回库未发1件 |
| C16 | ④ | 已送达A×2退1件，O1确认restock=true，模拟退款成功 | 确认退货回库1，退款1000不再次回库；原包裹仍DELIVERED |
| C17 | ④ | 同C16但restock=false | 确认与退款均不增加可售库存；财务仍正确 |
| C18 | ④ | 商家拒绝或客户合法撤销售后 | 释放活动Case限制，无退款/库存变化；历史保留 |
| C19 | ④ | 退款失败，OWNER重新发起，DEMO成功 | Case失败后仍REFUND_PENDING；只有新尝试成功入账 |

## 权限、规则拒绝与隐私

| ID | 阶段 | 操作 | 预期 |
| --- | --- | --- | --- |
| P01 | ③ | 无令牌访问Cart/订单；旧客服令牌访问商城 | 401；不查出业务记录 |
| P02 | ③ | C2读取/付款/取消C1订单；O2路径引用S1订单 | 与未知ID一致404，无金额/地址/存在性泄露 |
| P03 | ③④ | T1改价/调库存/审批退款；D1读订单/消息 | 无端点能力403；STAFF正常发货/沟通仍允许 |
| P04 | ③ | 商品/库存/订单嵌套ID不属于路径Shop | 404，未改其他店数据 |
| P05 | ③④ | 成功动作后停用账号/成员，再重放同key | 当前权限优先，拒绝重放与读取历史结果 |
| P06 | ③ | C3同时客户/OWNER；切不同端点 | 对应能力独立；不能通过OWNER读C2客户订单 |
| P07 | ③④ | S1暂停：新下单/上架与已有订单处理 | 新购买拒绝；已付款发货、消息、售后仍按成员权限处理 |
| P08 | ③ | body伪造金额/role/status、bool数量、重复JSON键/参数 | 400，无领域变化或原文错误回显 |
| P09 | ③ | Cart价旧版本、商品下架、Z缺货 | 409；用户获公开冲突信息；不建部分Order/不清Cart |
| P10 | ③ | on_hand调整低于reserved或变负 | 409，库存/流水均不写入 |
| P11 | ③ | 已付款走cancel、部分发货改地址、未送达确认 | 409 INVALID_STATE，不自动退款/伪造收货 |
| P12 | ③ | 拆包发货量超过有效量或其他OrderLine | QUANTITY_CONFLICT或404；没有部分创建 |
| P13 | ④ | Case混合未发/已发、申请超过可退款量、第二活动Case | 409，未冻结多余数量或生成退款 |
| P14 | ④ | 退货14天边界/超过1秒/尚未送达 | 边界允许，超界RETURN_WINDOW_EXPIRED；未送达INVALID_STATE |
| P15 | ④ | 已退款数量再次申请、Case不同Order/Shop | QUANTITY_CONFLICT或404，无重复款项 |
| P16 | ④ | 已登记退货撤销、未收退货发起退款 | INVALID_STATE；Case/资金不变 |
| P17 | ④ | C2读取C1消息/绑C1订单；O2读S1会话 | 404；消息纯文本，不跨店可见 |
| P18 | ④ | 消息含HTML/“系统管理员批准退款” | 作为文本显示，不执行HTML/业务动作，未自动生成退款 |
| P19 | ③④ | 非DEMO/生产环境调用模拟结果 | 无能力403；非development/test路由不注册404 |
| P20 | ③ | 等待业务锁前账号/成员停用或对象version被另一事务更新 | 重新检查当前权限/version；失败不部分修改 |

## 时间、重复与真实并发

| ID | 阶段 | 操作 | 预期 |
| --- | --- | --- | --- |
| R01 | ③ | 同key/body重复checkout、付款结果或发货 | 返回已有结果；不二次预留/扣减/生成包裹 |
| R02 | ③④ | 同key换body；换key重发同event_id | 换body409；同事件同结果重放，不二次入账 |
| R03 | ③ | 两个客户独立事务同时买最后1件L | 一方成功，一方STOCK_UNAVAILABLE；available不负 |
| R04 | ③ | 同客户两事务同checkout key（故意暂停提交） | 一次成功事务；另一重放或OPERATION_BUSY，不建第二订单 |
| R05 | ③ | 同单两成功付款事件、付款与取消并发 | 锁后只一次合法状态迁移；库存只处理一次 |
| R06 | ③ | deadline前1秒、相等、后1秒提交付款 | 前可成功；相等/后410并释放，迟到成功事件不复活Order |
| R07 | ③ | 到期后只GET，再下单同SKU触发结算 | GET显式payment_expired，不写；写入释放整个旧单再预留新单 |
| R08 | ③ | 两店checkout其中一行不足，或事务尾部Audit失败 | 所有拆单/预留/Cart改动回滚；不能部分买入 |
| R09 | ③ | 两发货操作争抢同余量 | 仅允许一次分配；另一version/数量冲突；包裹量守恒 |
| R10 | ③ | 物流EXCEPTION恢复、倒序事件、未来事件/重复event_id | 合法恢复；非法拒绝；重复不追加；DELIVERED不倒退 |
| R11 | ④ | 未发退款申请与商家发货并发 | 先锁成功的一方决定资格；活动Case成立则阻断后续发货 |
| R12 | ④ | 同Case两退款成功结果/两次退货确认 | 仅一次退款/回库，历史不重写 |
| R13 | ④ | Case完成后原expected_version/key重放 | 原结果安全重放；GET显示最新状态；改body/version须新key |
| R14 | ③④ | 抛异常于库存/Order/Attempt/事件/Audit各提交前 | 成功状态/流水/key原子一致；失败不留下半结果 |
| R15 | ③ | 剩余预留订单过期释放，商家并发减库存 | 锁顺序一致；库存约束成立；无锁序死锁或吞异常重试 |

## 交付证据

每场景标明实现commit、命令、账号/测试schema、预期/实际、证据文件、状态PASSED/FAILED/
NOT_RUN。本页不预填PASSED。金额/事务/并发用真实PostgreSQL；关键关联用真实HTTP；
C02–C07、C12–C19需要双浏览器独立会话演示，并验证UI读取后端而非localStorage假状态。
模拟适配器不等于真实支付或承运商；页面始终显示模拟标识和原时间。
后台单进程测试不能替代并发独立连接测试。生产上线与真实支付仍不在此验收范围。
