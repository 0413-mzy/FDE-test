# 范围与授权边界

日期：2026-10-07。产品方向以 [主计划](plans/01_core_plan.md) 为准。
旧项目“禁止完整电商平台”和“只做订单咨询”的范围不再约束新平台建设。

## 平台目标范围（分步实现）

- 多商家、实体商品、用户端与商家端、平台自有持久化业务记录。
- 商品/SKU、库存、购物车、下单与模拟付款、订单处理、发货与模拟物流。
- 用户查询物流、双方消息、确认收货、取消与退款/退货等售后。
- 权限隔离、状态校验、幂等与并发、审计、可复现演示数据及异常场景。

模拟支付、取消、地址修改与退款可以作为人工业务功能设计；不沿用旧客服模块的
全局禁止。具体前态、权限、金额/库存影响已在 [状态契约](commerce/lifecycle.md)定义，
第三步实现模拟付款、未付取消与地址修订；第四步新增退款/退货及双方消息。

未付取消/到期、地址修订、分包发货/物流/确认收货，以及连接同一后端的用户/商家/DEMO页面。

OWNER审核与回库、模拟退款结果及双端页面。使用增量0004迁移，保留现有订单。
第四步当时不部署或合并main，不进入第五步或AI；该步结果以

## 初版不覆盖

真实支付/清算、真实承运商与外部消息投递、实际经营上线、多币种/税费/报关、复杂促销、
数字商品、订阅交易、完整 ERP/CRM、通用 Agent/SaaS 平台以及 AI 自动执行业务。
这些需要独立需求与设计，不因“尽量覆盖业务”自动纳入第一版。

[既有契约](contracts/README.md)保持兼容模块的规则；平台新规则优先依据新主计划。

历史验证仅证明对应日期/版本，不作为新平台验收。

## 当前扩展：用户与商家入驻

用户选择先补齐账号和商家入驻类别，并明确先用本地模拟邮件，部署前再接真实服务。
新增注册/邮箱验证、恢复/修改密码、账户资料、地址簿与结账预填、入驻申请/撤回/独立审核。
批准在同一事务创建店铺和OWNER资格；普通客户和DEMO不能审核或自授权限。
使用增量0005迁移和显式reviewer Seed，保持旧账号、订单及库存。
契约见[commerce-onboarding-v1](commerce/onboarding.md)。不包括真实邮件、真实资质核验、公开部署或AI。
